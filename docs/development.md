# Contributing

Thank you for helping improve the block → Gram Panchayat downscaling system (SIH 2026).

## Ground rules

1. **No synthetic data in the pipeline.** Inputs, labels and covariates must come from a real, documented source
   registered in the provenance manifest (`src/common/manifest.py`). Synthetic data is allowed **only** as test
   fixtures in `tests/`.
2. **No leakage.** Every feature must be available on the forecast issue date. Anything computed from targets must
   be computed inside the training fold (see `src/features/bias_encoder.py`). Add a test to
   `tests/test_leakage_and_splits.py` for any new such feature.
3. **One source of truth for results.** Never type a metric into code, HTML or Markdown. Numbers come from
   `outputs/<district>/reports/evaluation.json`, and the README results block is regenerated by
   `python -m src.pipeline.run --only docs`.
4. **Report against baselines on unseen panchayats.** Model changes must report skill vs the naive block copy *and*
   vs the bias-corrected block, on the spatial hold-out × test period, with bootstrap CIs.
5. **Officer-editable settings live in YAML** (`config/advisory_rules.yaml`, crop calendars). The i18n catalogues
   (`src/advisory/i18n/*.yaml`) must stay key- and placeholder-complete across mr/hi/en; a test enforces this.

## Setup

```bash
python -m venv .venv
.venv/Scripts/activate           # Windows (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
pip install --no-deps -e .
```

## Everyday commands

```bash
ruff check src tests                        # lint (CI fails on any finding)
pytest                                      # unit + integration tests
python -m src.pipeline.run --only train evaluate report docs   # retrain and refresh every report
uvicorn src.main:app --port 8080            # dashboard
```

## Workflow

1. Create a branch: `git checkout -b feature/<name>`.
2. Keep commits focused, with conventional messages (`feat:`, `fix:`, `docs:`).
3. Make sure `ruff check` and `pytest` pass locally. CI runs both, plus a Docker build.
4. Open a pull request that describes the change and, for model changes, the before/after scores from `evaluation.json`.
